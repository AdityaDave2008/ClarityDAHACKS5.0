# Frontend

One shared application for both frontend contributors.

- Design-focused contributor: user flow, visual system, reusable components, accessibility, and design review.
- Newer contributor: small, agreed screens and forms, API wiring, loading, empty, success, and error states. Pair for unfamiliar work.

Coordinate ownership of individual files before editing shared components. Use [the API contract](../docs/api.md) for mocks and integration. Never embed backend secrets in browser code.

When choosing the stack, document exact install, development, build, and test commands here, plus safe public environment-variable examples. Keep component tests beside the app code.

First milestone: one user journey connected to the deployed backend, not just mock data.
